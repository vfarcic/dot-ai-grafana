`marked` moves from 12.0.2 to 18.0.11, and the answer renderer's raw-HTML suppression moves with it. marked 13 replaced positional renderer arguments with the token itself and stopped pre-escaping what it hands over: `image.text` is now the raw source, so the v12 override — which returned that argument untouched, correctly, because marked had already escaped it — would have become a raw-HTML passthrough had it simply been re-typed. `image` now flattens the alt through marked's `textRenderer` and escapes it here, and `link` parses its own child tokens so raw HTML in link text still re-enters the `html` override. Rendering is unchanged: images stay bare alt text, links stay `https:`-or-same-origin with `rel="noopener noreferrer"`, task-list state stays a `☑`/`☐` glyph. The DOM allowlist would have caught the element either way; the point is that the parser-level control, not the backstop, is what removes it. Pinned by tests that assert the tag survives as visible text, which only holds when the escape happens at the parser.
