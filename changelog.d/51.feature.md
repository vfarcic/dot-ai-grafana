dot-ai answers now render as sanitized Markdown — headings, lists, tables, code blocks and links — instead of plain text, through a new `ResponseMarkdown.tsx` renderer. The answer is treated as untrusted input, because it is model output built from cluster telemetry that anyone able to emit a log line or name a resource can influence: raw HTML is re-escaped to visible text at the parser, no remote-reference element (`img`, `iframe`, `video`, `audio`, `object`, `embed`, `svg`, `link`, …) is ever emitted, `style` is stripped from every tag, and only absolute `https:` or same-origin links survive — each with `rel="noopener noreferrer"`. Grafana's Text-panel sanitizer (`sanitizeTextPanelContent`) is deliberately not in this path: that whitelist is written for markdown an editor typed by hand and permits `<iframe>`, `<img>` and `style`, which is the wrong trade-off for model output derived from untrusted telemetry. A parse or sanitize failure falls back to escaped plain text rather than raw markup. Three rendering details worth knowing: markdown images show their alt text only, code blocks are unhighlighted, and task-list checkboxes render as ☑/☐ glyphs rather than form controls. Bare `https://` URLs in an answer become external links, marked with ↗ and titled with their destination so a click is never a surprise; `http://` and `www.` URLs are left as plain text. This adds `marked` as a runtime dependency and increases the plugin bundle (`dist/module.js`) from roughly 41 KB to roughly 79 KB, a ~93% increase.
